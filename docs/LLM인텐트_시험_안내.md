# LLM 인텐트 시험 안내 (2026-10-03)

음성 명령(PTT → STT → LLM) 중 **LLM 인텐트 분류** 구간의 정확도를 재기 위한 시험 도구와 문장 세트.
공모전 문서에 수치를 쓰려면 이 시험을 실제로 돌린 결과만 인용한다. 아직 돌리지 않았으므로 **현재 LLM 정확도 수치는 없음**.

## 1. 파일

| 파일 | 용도 |
|---|---|
| `tools/intent_testset.csv` | 시험 문장 210개(사용 대상 199개) + 정답 + 유형 + 검증 구분 |
| `tools/intent_eval.py` | 앱과 같은 프롬프트·요청·판정으로 LLM 시험 실행, 지표 보고서 생성 |
| `tools/intent_local_baseline.py` | 초기 로컬 TFLite 모델 재현 시험(참고용) |
| `tools/intent_eval_results/` | 실행 결과 폴더(`report.md`, `predictions.csv`, `confusion.csv`, `summary.json`) |

## 2. 실행 방법 (프로젝트 루트 `D:\capstone`)

1. 스크립트 점검 — API 호출 없음, 모의 분류기. **결과에 DRY-RUN 표시가 붙으며 인용 금지**

```bash
python tools/intent_eval.py --dry-run --yes
```

2. 빠른 시험 — 인텐트별 3문장, 약 30건

```bash
python tools/intent_eval.py --key-from-source --quick
```

3. 전체 시험 — core + boundary 199건 (동시 요청 2개, 수 분 이내)

```bash
python tools/intent_eval.py --key-from-source
```

4. 쉬운 문장만(core)·경계 사례만(boundary) 따로 보고 싶을 때

```bash
python tools/intent_eval.py --key-from-source --tiers core
```

- 실행하면 "N문장을 (호스트)로 전송합니다"가 뜨고 `y`를 입력해야 시작한다. **전송되는 것은 문장 텍스트뿐**(음성·영상 없음).
- 키는 `--key-from-source`(IntentClassifier.kt에서 읽음) 또는 환경변수 `INTENT_API_KEY`. 화면·결과 파일에 기록하지 않는다.
- 프롬프트·모델명·URL은 앱 소스에서 직접 읽으므로 앱과 항상 같은 조건이다. 응답 판정도 앱의 `mapIntent()`와 같다(응답에 포함된 첫 인텐트 토큰, 없으면 UNKNOWN).
- ⚠ 키가 `IntentClassifier.kt`에 하드코딩돼 있다. 소스를 제출 ZIP이나 공유 저장소에 넣기 전에 제거하거나 키를 교체할 것.

## 3. 보고서가 주는 지표

정확도(+95% 신뢰구간), 동작 기준 정확도(통화=일대일 동일 처리), 인텐트별 Precision/Recall/F1, 혼동행렬, **무관 발화 오작동률**(무관한 말인데 명령으로 실행되는 비율), 명령 미인식률, 응답 형식 준수율(토큰 하나만 반환하는지), 문장 유형별·검증 구분별 정확도, 응답 시간 p50/p95/p99, 오분류 전체 목록.
응답 시간은 **PC→게이트웨이** 왕복이며 폰 STT·BLE 구간은 포함하지 않는다(인수조건 10초와 직접 비교 불가).

## 4. 시험 문장 세트

- 인텐트 10종 × 20문장(UNKNOWN 30문장) = 210개. 유형: 표준 존댓말, 반말, 고령 화자 불완전 문장(조사 생략·어순 도치·군말), 사투리(경상·전라·충청·강원), 간접·완곡 표현, STT 오인식형, 경계 사례. UNKNOWN은 비언어 소리·무관 질문·**단어만 겹치는 무관 발화**(예: 지난 일 이야기).
- 로컬 모델 학습 문장 44개와 겹치는 문장은 제거했다(겹침 0).
- 검증: 정답을 숨긴 독립 라벨러 3인(일반 화자 / 고령 화자 전문가 / 엄격 규칙 적용)이 각자 라벨링.
  - `core` 175개: 3인 모두 정답과 일치하고 모호 표시 없음
  - `boundary` 24개: 불일치 또는 모호 표시가 있는 경계 사례
  - `drop_unnatural` 11개: 부자연스럽다는 판정으로 제외(과도한 격식체, 무의미 글자 4개 포함)
- **한계(반드시 알릴 것)**
  - 문장은 AI가 작성하고 AI가 검증했다. 같은 계열 모델에 유리해 **정확도가 실제보다 높게 나올 수 있다**. 사람이 읽고 확인하기 전에는 "높은 정확도"라고 단정하지 않는다.
  - 실제 고령 화자 발화가 아니다. 무의미 글자(STT 쓰레기) 사례는 제외돼 시험에 없다.
  - 문장 수가 작아 신뢰구간이 넓다. 수치는 문장 수·신뢰구간과 함께 쓴다.

## 5. 사람이 확인할 것

CSV는 Excel에서 열 수 있다(`utf-8-sig`). 고칠 때는 `intent`(정답)를 수정하거나 `tier`를 `exclude`로 바꾸면 시험에서 빠진다. `review` 칸은 메모용.

- `boundary` 24개 전체(CSV에서 `tier`가 boundary). 특히 정답이 의심되는 두 건:
  - id 81 `목소리가 좀 더 또렷하게 들리게 해줘` — 정답 VOLUME_UP이지만 라벨러 3인 중 2인이 UNKNOWN(명료도 요청)
  - id 42 `수동 운전은 이제 힘들어서 못 하겠어` — 정답 UNKNOWN이지만 라벨러 3인 모두 AUTO_MODE_ON 판단
- core에서 이상한 문장이 보이면 같은 방법으로 제외.
- 가능하면 **실제 어르신·가족 발화 10문장 이상**을 CSV 끝에 추가(`tier`=core, id는 새 번호). AI가 만든 문장의 편향을 줄이는 가장 효과적인 방법.

## 6. 결과를 문서에 쓰는 법

쓸 수 있는 형태(숫자는 실제 결과로 채움):

> 인텐트 10종, 시험 문장 N개(core a개·경계 b개, 팀 구성 후 검수)에 대해 LLM(claude-sonnet-5, 학교 AI 게이트웨이)의 인텐트 분류 정확도 x%(95% 신뢰구간 y~z%), 무관 발화 오작동률 w%. 시험 문장은 텍스트 직접 입력이며 STT 구간은 제외.

- "검수"는 **사람이 실제로 확인한 경우에만** 쓴다.
- 쓰면 안 되는 표현: "정확도가 높다/압도적이다"(결과 확인 전), "AI 모델이 고령 화자 발화를 정확히 이해한다"(실제 발화 미시험).

## 7. 초기 로컬 모델 재현 시험 결과 (2026-10-03, 참고)

`채원_Process.md`의 "비정형 발화 환경에서 40~45%"는 저장소에 시험 기록이 없어 직접 재현했다. `ptt_module/app/src/main/assets/intent_model.tflite`를 공식 TFLite 인터프리터와 numpy 재현(출력 차이 6e-8, 예측 44/44 일치)으로 돌렸다. 앱에 들어간 `vocab.txt`·`labels.txt`는 현재 `train_model.py` 데이터에서 만든 것과 완전히 일치한다.

| 시험 | 결과 |
|---|---|
| 모델이 **자기 학습 문장 44개**를 맞히는 비율 | **43.2%** (19/44) |
| 신규 시험 문장(모델이 아는 6종 정답, 122개) | 18.0% (22/122, 95% 신뢰구간 12.2~25.8%) — 6종 무작위 수준(16.7%)에 가까움 |
| 신규 문장의 미등록 어절 비율 | 평균 91.4% (41개 어절 사전에 없어 모두 0으로 처리) |

재현 방법(누구나 확인 가능):

```bash
python tools/intent_local_baseline.py --train-check --crosscheck
```

해석과 주의:

- 학습 문장에서의 43.2%는 채원 님이 적은 40~45%와 일치한다. 다만 **원인은 "비정형 발화"만이 아니다.** 모델이 자기 학습 문장조차 절반 못 맞히므로, 학습이 충분하지 않았거나(학습 44문장·100 epoch·배치 32) 구조적 한계가 있다고 보는 것이 측정과 맞다. 원인 단정은 피한다.
- 신규 문장 18.0%는 AI가 작성한 문장과 `train_model.py` 기준 전처리(앱의 실제 전처리 코드는 저장소에 없음)로 얻은 **참고치**다. 채원 님 당시 시험의 직접 검증이 아니다.
- 이 결과는 "44문장·41어휘로 만든 초기 프로토타입"에 대한 것이다. **"온디바이스 모델은 부정확하다"로 일반화하면 안 된다**(명세는 1,500문장 데이터셋·FastText를 목표로 했음).
- 권장 표현: "초기 로컬 모델 프로토타입(학습 문장 44개·어휘 41개)은 학습 문장에서도 정확도 43.2%에 그쳐 실사용 수준에 미달했고, 빌드 의존성 충돌과 함께 LLM API 방식 전환의 근거가 되었다."
- 채원 님께 두 가지 확인 요청: 40~45%가 어떤 시험에서 나온 수치인지, 위 재현 결과와 서술 방식이 맞는지.
