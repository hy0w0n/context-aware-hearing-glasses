# 4. 인수조건과 테스트 (현재 프로젝트 기준 개정안 v2)

## 읽는 법
- 3-1은 목표, 4-1은 이번 인수에서 합격으로 보는 기준이다. 3-1보다 느슨한 항목은 "원래 기준에서 바뀐 값" 표에 이유를 적었다.
- 기능시험은 "된다 / 안 된다"로, 성능시험은 숫자를 재서 기준과 비교해 판정한다.
- 합격선은 관측한 값 기준이다. 시험 개수가 적어서 참 성능을 보증하지는 못하므로, 결과는 k/n(성공 횟수 / 시험 횟수)과 오차 범위(95%)를 함께 적는다. 예를 들어 20회 중 16회 성공이면 참 성공률은 약 58~92%로 본다.
- 배터리, 온도, 이어폰 출력처럼 부품이 아직 없는 항목은 4-1에서 빼고 "나중에 시험하는 항목"에 모았다.
- "규칙표"는 앱의 모드 결정 규칙(구현 기준)이다. 설계서의 앙상블 표와 다른 점은 별표로 따로 적는다.

### 4. 규칙표 (앱 구현 기준)

| 이미지 장면 | 모드 결정 |
|---|---|
| 대화 | 소리가 무음이면 실내. 그 외에는 방향이 두 곳 이상으로 나뉘면 다인 대화, 아니면 일대일 대화 |
| TV | TV 시청 (소리와 무관) |
| 실내 | 소리가 말소리면 일대일 대화, 아니면 실내 |
| 야외 | 야외 (소리와 무관) |
| 알 수 없음(negative) | 소리가 말소리면 일대일 대화, 아니면 현재 모드 유지 |
| 위험 | 모드는 바꾸지 않고, 자동 모드일 때 알림만 표시 |

위험 소리는 이미지와 모드에 상관없이 알림을 표시한다 (10초에 한 번).

**별표: 설계서와 다른 점** 일대일과 다인 구분은 대화 장면일 때만 적용한다. 위험 이미지와 위험 소리가 겹쳐도 알림은 하나이고 더 강하게 표시하지 않는다. 실내 모드로 가는 음성 명령은 없다. 위험 알림 아이콘은 일반 경고 하나이고 표시 시간은 3초다 (설계서는 2초).

## 4-2. 기능시험 및 성능시험

시험 ID의 알파벳은 시험 영역(A 소리·방향, B 영상, C 판단·알림, D 음성 명령, E 통신, F 장시간 가동, G 개인정보), F는 기능시험, P는 성능시험이다. "해당 4-1 항목" 열은 항상 위 4-1의 ID를 가리킨다. "선행"은 본 시험 전에 확인하는 사전 점검이다.

### 공통 조건

- **구성 고정과 기록**: 안경 펌웨어 빌드, 소리 압축 켬(제품 구성), 이미지 VGA 3초 주기, 카메라 설정, 앱 빌드 시각, 모델 파일 해시, 음성 명령 서비스의 모델 이름, 폰 OS, 모드와 볼륨을 시험마다 기록한다. 보고서에는 시험 ID, 구성, k/n, 측정값, 영상 파일을 적는다.
- **재시도 규칙**: 모든 시도를 집계한다. 환경 문제로 무효로 한 시도는 사유와 함께 따로 적고, 다시 할 때는 같은 항목 전체를 처음부터 한다.
- **폰**: Galaxy S24 Ultra를 필수로 한다. 두 번째 기종이 있으면 통신과 분석 시간을 기종별로 따로 적는다. 시험 중 앱은 화면 맨 앞에 두고 화면을 켜 둔다 (백그라운드 동작은 아직 없다).
- **안경**: 방향과 거리 시험은 마네킹에 씌운다. 소리는 스피커로 거리 1m, 65~75dB(A)로 재생하고 파일 이름을 기록한다.
- **통신 기록**: 폰의 Wi-Fi 상태, 주변 2.4GHz 공유기 수, 협상된 연결 간격, 데이터 크기(MTU), PHY를 nRF Connect로 기록한다.
- **모드별 소리 차이**: 이어폰 출력이 없어서 폰으로 가는 소리에서만 확인한다. 현재 모드 사이의 차이는 저음 필터와 마이크 가중치뿐이다.
- **지연 측정 장비**: 외부 카메라 1대(60fps 이상, 소리 켬)를 고정하고, 한 화면에 안경 OLED와 폰 화면(터치 표시 켬)이 함께 보이게 한다. 읽기 오차는 ±1프레임(약 17ms)이다.

**시간을 재는 시작과 끝**

| 기준 | 시작 | 끝 |
|---|---|---|
| PR1 | 새 장면 카드가 렌즈를 가득 채운 첫 프레임 | OLED 모드 문구가 목표 모드로 바뀐 첫 프레임 |
| PR2 | 영상의 소리 트랙에서 소리가 시작되는 시점 | OLED 알림 화면이 처음 보이는 프레임 |
| PR5 | 앱 버튼 터치 표시가 처음 보이는 프레임 | OLED 변화가 처음 보이는 프레임 |
| PR6 | 안경 버튼을 뗀 시점 | OLED 변화가 처음 보이는 프레임 (자동 모드 켜기, 끄기는 앱 토글 표시) |
| PR12 | 안경 전원을 켠 시점 | 앱 파형이 다시 움직이기 시작한 첫 프레임 |
| PR16 | 앱이 이미지 시작 신호를 받은 시각 | 이미지 끝 신호를 받은 시각 (밀리초 로그) |

**시험 순서**: 1단계 구성 고정과 사전 점검(A-F5, B-F5, E-F1) → 2단계 기능시험 → 3단계 짧은 성능시험(지연, 정확도) → 4단계 장시간과 사람이 필요한 시험(60분, 음성 50문장, 대화 세션).

## 시험 전에 알아둘 점 (내부용, 명세서에는 넣지 않아도 됨)

현재 상태 그대로 시험하면 불합격이 예상되는 항목이다.
- **FR3, C-F6**: 방향을 알 수 없으면 지금은 정면(0°) 화살표를 표시한다.
- **E-F3**: 안경만 재시작하면 앱과 안경의 모드가 어긋나고, 앱이 같은 모드는 다시 보내지 않는다.
- **PR8**: 현재 모델로는 시간당 10회를 넘길 가능성이 높다 (팀 계산 추정이며 실측은 아님). 앱에서 위험 판정을 연속 2회 확인하는 방식을 넣으면 줄일 수 있다.
- **PR9**: 웹 사진 시험에서 72.3%였고 위험 0/6, TV 2/9였다. 안경 카메라 사진으로 다시 재야 한다.
- **D-F1**: 이전 기록에서 시리얼 10쌍 중 앱 8쌍만 보였다 (버튼 이벤트는 한 번만 보내고 재시도가 없다).
- **PR14, PR16**: 소리 압축이 기본 꺼짐이다. 압축을 켜야 통과 가능성이 있다 (압축 끈 상태는 이미지 동시 전송에서 2.84%, 이미지 0.8~1.0초가 기록됨).

3-1 값 중 현재 구조로는 맞출 수 없어서 수정을 권하는 항목이다.
- 자동 전환 2초 → 6초 이내, "최대 10초 간격 인식" → "영상 3초, 소리 2초마다 판단"
- 위험 알림 0.5초 → 4초 이내 (1초 이하는 안경이 직접 경고하는 경로를 만들 때만 가능)
- BLE 재연결 2초 → 10초 이내 (끊김 감지 최대 4초와 부팅 2초 때문)
- 오디오 처리 20ms → 이어폰 출력부 구현 후 40ms 이하 (20ms는 개선 목표)
- 배터리 8시간은 2000mAh 이상이 필요해 안경 무게 목표(100g 이하)와 충돌하기 쉽다. 무게 목표와 함께 다시 정해야 한다
- 정확도(90%, 95%)는 안경에서 측정하기 전이라 근거가 없다. 측정 후 확정
